Building an Isolated Active Directory Environment

The first step was setting up an isolated private network. This is done to prevent the DHCP Server from assigning IP addresses to my phone, printer, or other devices on my home Wi-Fi. I created a virtual machine in VMware, set max disk size to 60 GB, then went to hardware, network adapter, and created a LAN segment named AD-Lab.

I set up a static IP address so clients could find the server. Because this server was going to become the Domain Controller, it will also act as the primary DNS server for the whole lab (using loopback address 127.0.0.1).

Creating the Helpdesk Server (LAMP Stack)

Next, I built an osTicket helpdesk server using Ubuntu Server. Because this VM needs to access the Internet, it required two network adapters: one NAT for internet access, and one tied to the AD-lab LAN segment. I then installed Apache, MariaDB, and PHP.

To configure the database, I used MySQL:

CREATE DATABASE osticket_db;
CREATE USER 'osticket_user'@'localhost' IDENTIFIED BY 'LabPassword123!';
GRANT ALL PRIVILEGES ON osticket_db.* TO 'osticket_user'@'localhost';
FLUSH PRIVILEGES;

Troubleshooting Apache and PHP Conflicts

When attempting to reach the osTicket installer, I was greeted with raw PHP code. Apache on the newest version of Ubuntu uses a traffic-handing system called mpm_event that isn’t compatible with the PHP translator. I had to swap Apache’s traffic handler to the older mpm_prefork.

sudo a2dismod mpm_event
sudo a2enmod mpm_prefork
sudo a2enmod php*

After resolving this and securing the LDAP connection, I was able to successfully bridge the Linux Helpdesk environment with the Windows Active Directory domain to verify employee sign-ins.
